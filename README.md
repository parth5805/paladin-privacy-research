# Paladin Privacy Research

Independent technical research into the privacy model of [Hyperledger Paladin](https://github.com/LFDT-Paladin/paladin) — an Apache-2.0 privacy layer for EVM chains built on Hyperledger Besu.

Everything here is **verified against a live cluster** running Paladin v1.0.0 (released 2026-06-25), the current stable release. Where behaviour changed over time, the timeline is documented with commit hashes, PR numbers, and quotes from the maintainers.

---

## The one-line answer

> **Paladin v1.0.0 provides node-level privacy, not identity-level privacy.** Every identity hosted on a Paladin node that is a member of a privacy group can read and write that group's private state, whether or not the identity is itself listed in the group's members. Sub-node privacy is on the maintainers' roadmap but not shipped.

Reproducible proof at [evidence/live-run-truth-table.txt](evidence/live-run-truth-table.txt) — a 12-row truth table generated by running the demo in this repo against fresh Paladin v1.0.0.

## Runnable demo

[demo/](demo/) — a self-contained TypeScript demo that:
- Creates 2 privacy groups sharing 3 Paladin nodes
- Deploys a private `Storage` contract into each group
- Writes distinct secrets
- Tries to read each secret from every identity in the network
- Prints a coloured truth table showing exactly what is and isn't visible

Runs in about 90 seconds against a fresh Paladin v1.0.0 cluster.

## How to reproduce everything

### 1. Bring up Paladin v1.0.0 in a fresh Kind cluster

```bash
# Kind cluster with Paladin's port config
curl -LO https://raw.githubusercontent.com/LFDT-Paladin/paladin/refs/heads/main/operator/paladin-kind.yaml
kind create cluster --name paladin --config paladin-kind.yaml

# cert-manager
helm repo add jetstack https://charts.jetstack.io --force-update
helm upgrade --install cert-manager -n cert-manager --version v1.16.1 \
  jetstack/cert-manager --create-namespace --set crds.enabled=true

# Paladin
helm repo add paladin https://LFDT-Paladin.github.io/paladin --force-update
helm upgrade --install paladin-crds paladin/paladin-operator-crd
helm upgrade --install paladin paladin/paladin-operator -n paladin --create-namespace

# Wait for all 3 Paladin nodes Ready (~5 min while smart contracts deploy)
until kubectl -n paladin get pod paladin-node1-0 paladin-node2-0 paladin-node3-0 2>/dev/null \
  | awk 'NR>1 && $2=="2/2" && $3=="Running"' | wc -l | grep -q "^3$"; do sleep 5; done
```

### 2. Run the demo

```bash
cd demo
npm install
npm run start
```

You should see a truth table that matches [evidence/live-run-truth-table.txt](evidence/live-run-truth-table.txt).

### 3. Verify the code claims independently

```bash
# Fresh upstream clone
git clone --depth 5 https://github.com/LFDT-Paladin/paladin.git /tmp/paladin-verify
cd /tmp/paladin-verify

# The membership check that PR #872 briefly added is not in upstream anymore
grep -n "MsgPGroupsFromNotMember\|is not a member of privacy group" \
     core/go/internal/groupmgr/manager.go
# expected: no output (the check was reverted)
```
